# viz/personality-test

The dev workshop for the `/personality` skill: the non-slop color model, the
structural-slop detector, the build-time API those two feed, and the informal
A/B logs from iterating on the skill against real briefs.

**Production dependency:** `api.mjs` and the `color/` modules here are not
throwaway — they are imported directly by production and by tests:
- `scripts/build-service-bundle.mjs` imports `color/corpus.mjs`.
- `packages/pipeline/src/api.test.ts` shells out to `api.mjs` as a CLI.
- `packages/pipeline/src/color-density.test.ts` imports `color/color-space.mjs`
  and `color/density.mjs` directly.
- `apps/engine/engine.mjs`'s color/font logic is ported from `api.mjs` /
  `color/*` (see the comment at the top of that file).

## Pipeline order (color model)

1. `color/build-color-roles.mjs` — mines the role-aware color model from the
   feature crawl (`data/feature-crawl-raw.ndjson`).
2. `color/corpus.mjs` — assembles the density corpus: hardcoded framework
   default palettes (Tailwind/Material/Bootstrap/Open Props/daisyUI-Chakra-Ant)
   + every hex actually shipped in this directory's top-level `*.html` files
   (see the file for why `ab/` is deliberately excluded).
3. `color/density.mjs` — KDE "overused color" density field + hard-ban +
   nearest-safe-color suggestion, built on the corpus above.
4. `color/roles.mjs` — role-aware density + the palette gate (whole-palette
   verdict, not just individual hexes).
5. `color/validate.mjs` — CLI: detect + snap + suggest for a given color.
6. `api.mjs` — the single build-time entrypoint that wraps all of the above
   (`color`, `palette`, `audit`, `fix` commands) — this is what production
   code and tests actually call.

`structural-check.mjs` is the analogous detector for structural (non-color)
slop patterns (generic hero grid shapes, etc); `build-structural-prevalence.mjs`
and `build-structural-slop.mjs` compute/visualize how prevalent each pattern
is across the crawl corpus.

## Scripts (one line each)

- `api.mjs` — **production** build-time API: get non-slop colors/fonts/styles, audit + auto-fix a built page.
- `color/corpus.mjs` — assembles the "AI-overused color" corpus (framework defaults + our own shipped hexes).
- `color/density.mjs` — KDE overuse density field + hard-ban + nearest-safe-color, **production** (imported by pipeline tests).
- `color/roles.mjs` — role-aware density + whole-palette gate.
- `color/color-space.mjs` — pure color-space conversions, **production** (imported by pipeline tests).
- `color/validate.mjs` — CLI validator: detect + snap + suggest for one color.
- `color/build-color-roles.mjs` — mines the role-aware color model from the feature crawl.
- `color/build-color-roles-viz.mjs` — generates `color/color-roles.html` viewer.
- `color/build-color-slop-ranked.mjs` — generates `color/color-slop-ranked.html` (colors ranked by overuse).
- `color/build-color-space-map.mjs` — generates `color/color-space-map.html` (bucketed color-space map).
- `color/build-density-map.mjs` — generates `color/density-map.html` (visual sanity check of the density field).
- `color/reindex-getdesign-identity.mjs` — root fix for brand-attribution slop in the old per-hex dump pipeline.
- `structural-check.mjs` — structural-slop detector (generic layout patterns) for one or more HTML files.
- `build-structural-prevalence.mjs` — computes `data/structural-prevalence.json` (% of crawl sites exhibiting each pattern).
- `build-structural-slop.mjs` — generates `structural-slop.html`, a visual browser of structural-slop prevalence.
- `slop-check.mjs` — grounded objective slop checker used by the informal A/B tests.
- `diversity.mjs` — variety reporter: given N builds of the same brief, measures whether they actually differ.
- `contrast-audit.js` — snippet run via Playwright `browser_evaluate` to grounded-audit text/background contrast on a live page.
- `build-font-embedding.mjs` — joins `data/font-projection.json` + `data/fonts.index.json`, generates `font-embedding.html` (see "Font maps" below).
- `build-cross-gate.mjs` — generates `cross-gate-sites.html`; see the in-file comment for why it deletes any stale copy before the corpus loads.

## Font maps — which one is canonical

Two font-map visualisations are generated from overlapping-but-different data;
neither is the app-facing one:

- **`viz/font-projector.html`** — generated by `scripts/build-projection.py`.
  UMAP projection of the raw 384-d DINOv2 font embeddings; AI-slop fonts (high
  display saturation) glow as additive red clouds. Regenerate with
  `python scripts/build-projection.py` (needs `numpy`/`umap`).
- **`viz/personality-test/font-embedding.html`** — generated by
  `build-font-embedding.mjs`. Joins the projection with `fonts.index.json`
  metadata (supplier, matched/unmatched names) for a richer, labeled browser.
  Regenerate with `node viz/personality-test/build-font-embedding.mjs`.
- **`apps/web/viz/font-map.html`** — **not owned by this directory** (built by
  `apps/web/build/index-act.js`); it's the app-facing production build output.
  Do not confuse it with the two prototypes above.

If you just want "the current font map to look at," use `font-embedding.html`
(has metadata); if you want the raw embedding-space sanity check, use
`font-projector.html`.

## RESULTS*.md — status

These are informal, unblinded, single-author dev logs (N=1–5 builds per
round), each with a banner at the top saying so. `RESULTS-ab.md` additionally
scores builds with `api.mjs audit` — the same checker the treatment is built
to satisfy — so it is not evidence of superiority, just a self-consistency
check. For an actual blinded comparison harness, see `benchmarks/ui-skills/`.

## Other

- `*.html` / `*-full.png` (outside `ab/`) — dev-log build artifacts referenced
  by the `RESULTS*.md` files above; the `ab/*.html` variants are a rapid

  `color/corpus.mjs`).
- `*.html.bak` — stray backups left over from editing; harmless, not cleaned
  up as part of this pass since deleting isn't in scope here.
