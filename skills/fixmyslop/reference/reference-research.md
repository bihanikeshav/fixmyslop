# fixmyslop reference — Reference research & provenance

_Craft knowledge to draw on, not a template. The gates in design-law.md are the only hard rules — invent for THIS subject and diverge freely._

When the user supplies bookmarks, screenshots, inspiration sites, component libraries, or another skill as a quality target, build a small reference ledger. Record the source URL, license for code/assets, observable mechanic, subject fit, failure condition, and what will be regenerated from the current brief. Cluster duplicates before designing.

Extract mechanics, not skins. Strong references often make one real relationship legible: a dependency graph, scrubbable transformation, annotated state transition, product-native dashboard, or evidence ledger. Choose at most one high-commitment mechanic per viewport. 3D, canvas, particles, kinetic type, custom cursors, and ambient motion need a semantic job plus static, reduced-motion, touch, and narrow-screen translations.

Component and template libraries are search spaces. Reuse accessible primitives when licensing permits, but regenerate palette, typography, composition, copy, and focal behavior from this subject and the engine gates. Report intent fidelity, mechanism legibility, hierarchy, system coherence, task-state completeness, responsive recomposition, access resilience, and provenance independently. A passing deterministic scanner is necessary evidence, never proof of taste.
