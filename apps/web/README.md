# apps/web

The static frontend for fixmyslop, served by the `fixmyslop` Cloudflare
Worker's static-assets binding (`apps/worker/wrangler.toml`, `[assets]
directory = "../web"`). GET/HEAD requests are matched against this directory
first; anything with no matching file (`POST /mcp`, `/api/*`, `/install`,
`/skill`, `/health`, `GET /sse`) falls through to the Worker itself.

## Pages

| Path | What it is |
| --- | --- |
| `index.html` | **The real product.** The "decision bench" (Generate / Audit / Humanize) — a React app compiled from `demo/app.jsx` into `build/app.js` and bootstrapped by `build/engine-bootstrap.mjs`, which loads the connected design engine (`apps/engine/*`, copied into `build/apps/engine/` at build time) directly in the browser. |
| `dashboard.html` | A second, hand-written, self-contained page: the "Palette Lab" + "Type Foundry" + MCP pitch. Wired up by the standalone `app.js` (this directory, not `build/`), which imports `vendor/engine.mjs` directly — no build step. **This page predates `DESIGN.md`'s Evidence Workbench system and uses an off-spec palette/type system; see "Known design-system divergence" below.** It links to `index.html` (`./`) as "Open the workbench." |
| `viz/*.html` | Five standalone data-visualization pages (font similarity map, color-slop ranking, OKLab color space, KDE density heatmap, cross-gate corpus browser), linked from `index.html`'s "Visual Field" section. **Generated artifacts — do not hand-edit.** Each embeds its data inline at generation time. Generators: `viz/personality-test/build-cross-gate.mjs` → `sites-gates.html`, `viz/personality-test/color/build-color-slop-ranked.mjs` → `color-lanes.html`, `viz/personality-test/color/build-color-space-map.mjs` → `color-space.html`, `viz/personality-test/color/build-density-map.mjs` → `slop-density.html`, `scripts/build-projection.py` → `font-map.html`. (See also `AGENTS.md` rule 3: "Generated files... `apps/web/viz/*.html`... Change the generator, not the output.") |

`archive/web-slop-o-meter/` (repo root, sibling of `apps/`, **not** served —
outside the Worker's `[assets] directory`) holds a third page, the
"Slop-o-meter," that used to live here. It was broken (never mounted its own
layers) and was the "parody-first museum" `PRODUCT.md` rules out; see
`archive/README.md` for the full story.

## Source vs. build output vs. vendor

- **Source** you edit by hand: `index.html`, `dashboard.html`, `app.js`,
  `js-flag.js`, `_headers`, `demo/app.jsx`, `demo/app-styles.css`,
  `demo/engine-bootstrap.mjs`, `viz/*.html` generator inputs (elsewhere in
  the repo, not here).
- **`demo/textslop-summary.js`** — generated by `python textslopbench/export_web_summary.py` (TextSlopBench ledger, `window.TEXTSLOP_SUMMARY`); kept in sync by `tests/test_local_benchmarks.py`. No live page loads it at the moment.
- **`build/`** — generated by `scripts/build-web.mjs`, **git-ignored**, never
  hand-edited. It holds: `app.js` (compiled from `demo/app.jsx` via
  TypeScript's JSX transpiler, no bundler), `engine-bootstrap.mjs` (a copy of
  `demo/engine-bootstrap.mjs`), and a full copy of the connected design
  engine (`apps/engine/*.mjs` + `apps/engine/data/*`, the `master-v2`
  research JSON, and `viz/layout-embeddings/genome-vector.mjs`) — all served
  as native ESM so the browser can `import` them directly, no bundling step.
- **`vendor/`** — the standalone (non-connected) engine used by
  `dashboard.html`'s `app.js`: `vendor/engine.mjs` plus its
  `vendor/data/{corpus,brands,fonts}.json`. This is a separate, simpler
  implementation from the one in `build/apps/engine/`; the two are not meant
  to be merged (`dashboard.html` is a legacy surface — see below).

## Build pipeline

```
npm run build:web    # node scripts/build-web.mjs  — compiles demo/app.jsx into build/,
                      # copies the connected-engine runtime into build/, and stamps
                      # index.html's cache-busting ?v= query with a content hash
npm run test:web      # node scripts/check-web-build.mjs — asserts index.html ships
                      # production (not development) React, references only files that
                      # exist, and that the compiled bundle/bootstrap/stylesheet still
                      # carry the accessibility + responsive-layout contracts they must
```

`scripts/build-web.mjs`'s `entries` list only compiles what a live page
actually loads (`app.jsx`, for `index.html`). If you add a new page or
component that should ship, add its `.jsx` entry there and reference the
compiled `build/*.js` output from the page that needs it — don't add a
`<script>` tag pointing at an uncompiled `demo/*.jsx` file (browsers can't
run JSX).

### Cache-busting

`index.html` loads `demo/app-styles.css?v=<hash>` and
`build/engine-bootstrap.mjs?v=<hash>` where `<hash>` is a 10-character
SHA-256 prefix of `demo/app-styles.css` + `demo/engine-bootstrap.mjs` +
compiled `build/app.js`, stamped into `index.html` in place every time
`npm run build:web` runs. It used to be two independently hand-bumped
`?b=51` / `?b=52` counters that could (and did) drift out of sync — don't
reintroduce that. If you edit `index.html`'s `<link>`/`<script>` tags by
hand between builds, leave the `?v=...` value as-is; the next `build:web`
run overwrites it.

## Running locally

There is no dev server config here. Point any static file server at this
directory (e.g. `npx serve apps/web` or Python's `http.server`) after
running `npm run build:web`, then open `/index.html` or `/dashboard.html`.
`viz/*.html` and `demo/app-styles.css` etc. are plain static files and need
no build step of their own.

## Known design-system divergence

`dashboard.html` predates `DESIGN.md`'s "Evidence Workbench" creative north
star. It ships its own palette (`--paper`, `--accent: #c8175a` magenta,
etc.) and its own type system (Fontshare's Rowan/Technor for display/body)
instead of the tokens `DESIGN.md` now specifies. This was a deliberate
decision on this pass, not an oversight: `dashboard.html` is being left as a
legacy surface rather than redesigned (see the HTML comment at the top of
the file). `index.html` is the page that should be held to `DESIGN.md`.

## Security headers

`_headers` (Cloudflare static-assets format) sets a Content-Security-Policy
scoped to the origins the live pages actually load (enumerated by grepping
for every `https://` reference), plus `X-Content-Type-Options` and
`Referrer-Policy`. `js-flag.js` exists solely so `dashboard.html`'s one
inline `<script>` (`document.documentElement.classList.add('js')`) could
move to an external file, keeping `script-src` free of `'unsafe-inline'`.
